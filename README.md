# 写真まとめて整理

写真の圧縮・JPEG変換と、Jpegrm V4互換のEXIF撮影日時によるファイル名整理を、Windows上で行うデスクトップアプリです。

既定の設定は次のとおりです。

- 幅・高さを20%に縮小
- JPEG品質の上限は80
- 初期状態では自動調整せず、20%・品質80をそのまま適用
- 必要な場合のみ「ファイル容量を指定する（任意）」を開き、150KB以下などを指定可能
- 縦横比を必ず維持し、写真を引き伸ばさない
- 元画像は変更せず、保存先の `converted` フォルダへ出力
- 写真の向きは画素へ反映し、GPSなどの撮影情報は出力しない
- 同名ファイルがある場合は `_2`、`_3` を付け、上書きしない

ファイル名整理モードでは、次の安全策を標準にしています。

- Jpegrm V4と同じ `YYYY_MM_DD_HHMM_NN.jpg` 形式
- 元のJPEGはリネームせず、`converted` フォルダへ新しい名前でコピー
- 実行前に「元の名前 → 新しい名前」とスキップ理由を常に表示
- 撮影日時はV4と同じ `YYYY_MM_DD_HHMM` に固定
- 撮影日時・連番・メーカー名・機種名・自由入力を、横に並ぶ部品として追加して好きな順番へ並べ替え
- サブフォルダ走査は初期OFF。ONにした場合も `converted` 内へ元のフォルダ構成を維持
- 既存ファイルは上書きせず、連番を進めて回避

## 利用者向け

リリースから `ImageCompressor-windows.zip` をダウンロードして展開します。中にある「はじめにお読みください.pdf」を開き、記載された順番で操作してください。

配布された `ImageCompressor.exe` をダブルクリックします。利用者側でPython、uv、ImageMagick、WindowsのHEIF画像拡張機能をインストールする必要はありません。HEICの読み込みに必要なライブラリもexeへ同梱します。

exeは現時点ではコード署名をしないため、ダウンロード後の初回起動時にWindows SmartScreenの警告が表示される場合があります。

1. HEIC写真を複数まとめて、または写真フォルダごと、水色の枠へドラッグ＆ドロップします。ドラッグが難しい場合は「フォルダ選択…」を使います。
2. 保存先は自動的に `converted` になります。必要なら変更します。
3. 「○枚を元を残して変換」を押します。
4. 完了後に「保存先を開く」を押してJPEGを確認します。

写真を選ぶと、一覧にサムネイル・現在の寸法・容量を表示します。変換後の予想サイズは「サイズを計算」を押したときだけ計算します。写真の選択や設定変更では自動計算せず、計算せずに変換することもできます。名前整理では画像サイズを計算しません。画像サイズとJPEG品質はスライダーや数値欄で調整できます。

対象はドロップした `.heic`、`.heif`、`.jpg`、`.jpeg`、`.png`、`.webp` です。フォルダをドロップした場合は、そのフォルダ直下の写真を処理します。サブフォルダは処理しません。

初期状態では、Windowsフォトと同様に20%・品質80で保存します。写真の内容によってファイルサイズは変わります。容量の上限が決まっている場合だけ「ファイル容量を指定する（任意）」へチェックを付けると、目標サイズの入力欄が表示されます。

## ヘルプ・選択した写真を直接変更する

右上の「ヘルプ」またはF1キーで、アプリ内の取扱説明書とバージョンを表示します。「基本の使い方」「圧縮・JPEG変換」「名前の整理」「困ったとき」の4つのタブで操作手順を読めます。本文はスクロール・文字選択ができ、Escキーで閉じられます。PDFビューアーは不要です。配布ZIPには引き続き「はじめにお読みください.pdf」を同梱します。

「写真を選択…」で複数の写真を選択できます。一覧にはサムネイルを常時表示し、行をクリックすると右側に写真を大きく表示します。処理するのはチェックした写真だけです。チェックを外した行はグレーで残り、写真の確認と再チェックができます。Spaceキーでも切り替えられます。「すべてチェック」「すべて外す」でまとめて切り替えられます。実行ボタンには対象枚数を表示します。

- 「○枚を元を残して変換」：従来どおり保存先（既定は `converted`）へJPEGを出力します。
- 「○枚を上書き変換…」：確認画面の写真だけを元の場所で変更します。JPEGはファイル名・拡張子を維持して上書きし、他形式は同じ場所に `.jpg` を保存してから元ファイルを削除します。同名の別JPEGがある場合は、その写真を変更せずエラーにします。
- 名前整理モードの「○枚の名前を変更…」：画像の内容・EXIFを維持して同じフォルダ内で名前を変えます。既存の写真は上書きしません。実際の変更名は確認画面に一覧表示されます。保存先の違いにより、コピー用プレビューと連番が異なる場合があります。

上書き変換は元に戻せません。通常の変換と同様に、撮影日時・GPSなどのEXIF情報も除去します。名前整理も使う場合は先に名前を整理してください。中止しても処理済みの変更は残ります。直接処理の終了後は再圧縮を防ぐため対象を解除するので、続ける場合は写真を選び直してください。

## 撮影日時でファイル名を整理する

1. 画面上部で「撮影日時で名前を整理」を選びます。
2. JPEGまたはフォルダをドラッグ＆ドロップします。
3. 「部品を追加」でメーカー名・機種名・自由入力などを追加します。
4. 横に並んだファイル名の部品をドラッグするか、左右ボタンで好きな順番へ並べます。標準はV4と同じ「撮影日時 → 連番」です。
5. 自由な文字を付けたい場合は「＋ 自由入力」を押して入力します。撮影日時の形式はV4標準の `YYYY_MM_DD_HHMM` です。
6. 一覧の「今のファイル名」と「変更後のファイル名」を見比べます。変更できない写真はチェック不可になり、理由を名前欄に表示します。実行後は「コピーしました」「名前を変更しました」と表示します。
7. 「○枚を別名でコピー」を押します。確認画面の後、`converted` へコピーされます。

名前の例は次のとおりです。

- 標準: `IMG_1001.JPG` → `2025_10_17_1117_00.jpg`
- 「メーカー名」を末尾へ追加: `IMG_1001.JPG` → `2025_10_17_1117_00_SONY.jpg`
- 「機種名」を末尾へ追加: `IMG_1001.JPG` → `2025_10_17_1117_00_ZV-E10M2.jpg`
- 「自由入力」に「横浜中華街山下公園」を指定: `IMG_1001.JPG` → `2025_10_17_1117_00_横浜中華街山下公園.jpg`
- 「自由入力」を先頭へ移動: `IMG_1001.JPG` → `横浜中華街山下公園_2025_10_17_1117_00.jpg`

対象はJPEGのみです。EXIFなし、撮影日時なし、読み込み不能のファイルはコピーせず、理由を一覧に表示します。サブフォルダも対象にする場合は「サブフォルダも含める」をONにします。出力先の `converted` 自体は再走査しません。

## Windowsで実行・ビルドする

開発環境と依存ライブラリは `uv` で管理しています。まず[uvの公式手順](https://docs.astral.sh/uv/getting-started/installation/)でuvをインストールしてください。Python本体はuvが自動で用意します。

`run.bat` をダブルクリックするとソースから実行できます。初回のみPythonと必要なライブラリをインストールします。

配布用の単体exeを作る場合は `build.bat` をダブルクリックします。完成物は `dist\ImageCompressor.exe` です。ビルドはWindows上で行ってください。

公開GitHubリポジトリでは、Actionsの「Build Windows app」を手動実行すると、次の2ファイルをまとめた `ImageCompressor-windows.zip` をダウンロードできます。

- `ImageCompressor.exe`
- `はじめにお読みください.pdf`（非エンジニア向けの導入・操作手順書）

CIは `windows-latest` 上でテストとexe生成を行い、完成したexe自身でHEIC変換・名前整理・埋め込んだバージョンの検証を通してからZIPを作成します。

### リリースとバージョン

バージョンは `2026.0905.0` のような `YYYY.MMDD.連番` 形式です。月日を4桁に揃え、`v`は付けません。同日の追加リリースは末尾の連番が増えます。

1. `main`の更新でtagprがリリースPRを作成・更新します。
2. リリースPRをマージすると、tagprがCalVerタグとGitHub Releaseを作成します。
3. 同じワークフローの後続ジョブがそのタグをチェックアウトし、Windows版をビルドしてZIPをReleaseに添付します。

[`shuntaka-dev`](https://github.com/shuntaka9576/shuntaka-dev)と同じく、`.tagpr`で `calendarVersioning = YYYY.0M0D.MICRO`、`versionFile = -`を指定しています。[tagprの出力](https://github.com/Songmu/tagpr/tree/v1.20.1#outputs-for-github-actions)を後続ジョブへ渡すため、`GITHUB_TOKEN`によるタグpushで別ワークフローが起動しない場合にもビルドできます。手動のCalVerタグpush、タグを選んだ手動実行も対応します。

ビルド前に `tools/write_build_info.py` がGitから `build/build_info.json` を生成し、PyInstallerでアプリに埋め込みます。ヘルプはその値を表示し、配布先にGitやソースコードは不要です。`pyproject.toml`のパッケージ管理用versionはアプリの表示には使用しません。

- 正式なタグ上・変更なし：`2026.0905.0`
- タグ以降の開発版：`2026.0905.0-dev.3+abcdef0`
- まだタグがない開発版：`dev+abcdef0`
- 未コミットの変更あり：上記に `.dirty` を付加

リリース用CIは `--release-tag` を指定し、タグの形式・HEADとの一致・変更のないチェックアウトを検証します。古いタグや未コミットの変更を正式版として配布しません。ローカルの `build.bat` / `build-mac.sh` もGitから自動取得します。

GitHubの Settings → Actions → General → Workflow permissions で **Allow GitHub Actions to create and approve pull requests** を有効にする必要があります。通常のワークフロー権限はreadのままとし、tagprジョブだけにリリースPR・タグ作成に必要な権限を指定します。最初のリリースもtagprから作成でき、事前にタグを手作業で作る必要はありません。

## 開発

よく使う操作はMakefileへまとめています。
Makefileは `uvx` 経由でプロジェクト指定のuvを使うため、手元のuvが古くてもそのまま実行できます。

GUI確認用のJPEG一式は `tests/fixtures/Jpegrm-GUI-test-data` にあります。基本の連番、メーカー・機種、スキップ理由、サブフォルダ走査、既存ファイルとの衝突回避を、名前付きのフォルダごとに確認できます。フォルダ内の `テストの使い方.txt` も参照してください。

```bash
make run
make test
make self-test
make build-mac
```

個別にuvコマンドを実行する場合は次のとおりです。

```bash
uv sync --frozen --all-groups
uv run --frozen pytest
uv run --frozen python app.py --self-test
uv run --frozen python app.py
```

Macでテスト用アプリを再作成する場合は `./build-mac.sh` を実行します。固有のバンドルIDとアプリアイコンを設定した `dist/ImageCompressor.app` が作成されます。

依存バージョンは `uv.lock` に固定し、リポジトリへコミットします。HEICの読み込みには `pillow-heif`、画像処理には Pillow、Windows用exeの作成には PyInstallerを使っています。

元の場所で処理した後も一覧と写真を残し、二重処理を避けるためチェックを解除します。続ける写真に再びチェックを入れてください。
